# Материалы для README

Приложение уже работает. Проверенные команды запуска, актуальные возможности, ограничения и сценарий защиты находятся в [RUNBOOK.md](RUNBOOK.md). Этот документ остаётся структурой для README; старые формулировки «планируется» следует сверять с RUNBOOK.

## Обновление для текущего этапа

- Полная проверка ТЗ и границы качества: [SPEC-AUDIT.md](SPEC-AUDIT.md). Проверены 37 тестов, десять live-сценариев и 91 800 сочетаний по всему календарю. README обновлён только по этим фактам; изменения коллеги `fd868b0` сохранены.
- Объяснения больше не считают метафоры оборудованием, а «через 10 лет откроете фото» — опытом. Конкретные релевантные цитаты имеют приоритет; семь описаний получают честную отметку о недостатке конкретики. API добавил `summary` и `explanationEvidence.quality`.
- Причины короткой и пустой выдачи видны сразу. Если все заняты, увеличение бюджета не предлагается. `max_hours: null` отображается «без привязки к часам».
- Блок «Можно посмотреть иначе» стал компактнее; кнопки идут рядом с переносом на узком экране.

- Уточнение интерфейса: плавающий микрофон удалён, запись только в чате рядом с отправкой. Портреты круглые, с крупным лицом; анкета по-прежнему открывается отдельно.
- Готовые запросы показывают дату 15 октября 2026, город и бюджет; нажатие сразу запускает подбор. Названия: «Ведущий на корпоратив», «Флорист на корпоратив», «Ведущий до 100 тыс. ₸». Скрытых ограничений языка/часов в этих кнопках нет. Чат по-прежнему уточняет недостающие поля и просит подтверждение.
- После поиска пишем «Найдено 3 варианта» без «3 из 3»; блок подтверждения скрыт до изменения запроса. Аня использует женскую AI-иллюстрацию, Сон Гоку — мужскую.
- Для прежнего фиксированного сценария 15/17 октября условия задаются в «Ручном режиме», как описано в DoD. В любом подборе максимум три карточки.

- Теперь это **AI-режим агрегатора**, а не отдельный маркетплейс. Единый чат с карточками в ответах, независимый «Ручной режим» с фильтрами и выдачей под ними; общее локальное избранное открывается из шапки.
- Голосовой интерфейс подключён; настоящий API проверен на синтетической записи. Утверждать тест физического микрофона не нужно.
- `/api/agent` заменён на `/api/brief`: черновик → уточнения → подтверждение → `/api/search`.
- Двигатель возвращает индивидуальный факт и источник, а также точные ID занятых на дату анкет.
- **37 тестов и десять live-сценариев DoD проходят.** Максимум в измерении 2,746 с, повтор 13 мс, ориентировочная стоимость всего текстового прогона $0,00436.
- Сценарий защиты: [DEFINITION-OF-DONE.md](DEFINITION-OF-DONE.md). Интеграция: [ENGINE-API.md](ENGINE-API.md). Измерения: [DOD-RESULTS.json](DOD-RESULTS.json).
- Изображения явно помечены AI-иллюстрациями; реальные контакты, отзывы и рейтинги отсутствуют в исходных данных и не выдумываются.

## Что уже можно написать

- Название: LPV Match (рабочее).
- Назначение: умный подбор подрядчиков мероприятий по заданию Firebird, трек «Креативные индустрии».
- Ввод: город, дата, категория, формат, бюджет; дополнительные поля — язык, длительность, пожелания.
- Целевой результат: до трёх подходящих анкет с объяснениями; понятная причина, если выборка пуста.
- Основной подход: строгие ограничения и стабильный порядок обеспечивает код, работа с естественным языком и объяснения — LLM.
- Каталог: данные организаторов, 66 анонимизированных анкет, включая синтетические и дополненные поля. Метки происхождения сохраняются.
- Дообучение не планируется, отдельная видеокарта и база данных не нужны.
- Ключи API пользователь задаёт локально; настоящие ключи не публикуем.
- Участники: разработка и интеграция — Ербол; документация и демонстрационный сценарий — второй участник (имя добавить самостоятельно).

## Рекомендуемая структура README

1. Краткое описание задачи и ценности решения.
2. Что реализовано — обновлять по фактическому состоянию.
3. Требования, установка, переменные окружения и запуск — команды будут подтверждены сборкой.
4. Архитектура и распределение задач между кодом и моделями.
5. Формат и происхождение данных; ограничения начальной цены и календаря.
6. Три демонстрационных запроса: массовая категория, редкая категория, отсутствие результатов.
7. Проверки, известные ограничения, использованные библиотеки и модели.
8. Участники и распределение работы.

Архитектура и критерии готовности: [IMPLEMENTATION.md](IMPLEMENTATION.md). Типы данных: [src/domain/types.ts](../src/domain/types.ts). Не утверждать, что API или модель уже протестированы, пока соответствующая проверка не завершена.
