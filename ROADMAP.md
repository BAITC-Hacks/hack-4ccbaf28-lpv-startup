## 1. Каталог и алгоритм подбора — реализовано

- [x] Импортировать официальный CSV и проверить 66 анкет, обязательные поля и метки происхождения данных.
- [x] Реализовать ограничения по городу, категории, занятости, бюджету, формату, языку и длительности.
- [x] Добавить детерминированное ранжирование со стабильным порядком при одинаковых баллах.
- [x] Возвращать не более трёх анкет и различать `matched`, `no_category` и `no_matches`.
- [x] Проверить граничные случаи тестами: занятость, превышение бюджета, ограничения и повтор одного запроса.
- [x] Предлагать альтернативы даты и бюджета только после повторного поиска с соблюдением остальных условий.

Реализация: [доменный модуль](src/domain/matching.ts), [схемы](src/domain/schema.ts), [импорт](scripts/import-catalog.ts) и [тесты](tests/matching.test.ts). Проверки охватывают 6600 запросов по официальному календарю. Локальные объяснения и проверяемые основания доступны в карточках.

## 2. Интерфейс — реализовано

- [x] Добавить зависимости Next.js, React и TypeScript, lock-файл и команды разработки, сборки, импорта и проверок.
- [x] Создать страницы приложения Next.js и подтвердить запуск интерфейса.
- [x] Реализовать форму и карточки подрядчиков с начальной ценой.
- [x] Показывать причины пустой выдачи и действительное количество результатов, если найдено меньше трёх.
- [x] Обновлять подбор при повторном поиске с изменённой датой или другими условиями.
- [x] Добавить демонстрационные запросы на основе фактических данных каталога.

Реализация: [интерфейс](src/components/match-app.tsx) и [страница приложения](src/app/page.tsx). Production-сервер и основные сценарии локального режима проверены.

## 3. Модели и расход API — реализовано

- [x] Добавить серверный разбор естественного языка, уточнения и отображение распознанных полей в редактируемой форме.
- [x] Сформировать индивидуальные объяснения только из фактов об анкетах и проверенных цитат.
- [x] Подключить настраиваемые модели для разбора и объяснений; проверить их доступность на аккаунте команды.
- [x] Ограничить контекст выбранными анкетами и длину ответов, кешировать одинаковые запросы.
- [x] Показывать модель, задачу, фактические токены, задержку и оценочную стоимость.
- [x] Проверить локальный режим без ключа и при ошибке API с явным обозначением отсутствия LLM.

Реализация: [агент](src/server/agent.ts), [сервис поиска](src/server/search-service.ts), [адаптер OpenAI](src/server/openai.ts). AI-тесты используют имитацию ответов провайдера; ручная проверка реального API описана командой в [RUNBOOK](docs/RUNBOOK.md). Модель не определяет состав и порядок выдачи, ключ используется на сервере. Доступность выбранных моделей на другом аккаунте нужно проверить отдельно.

- [x] Дополнить README проверенной инструкцией запуска веб-приложения и production-сборки.
- [x] Подготовить сценарий демонстрации и описать ограничения учебного каталога, AI, кеша и учёта расходов.
- [ ] Перед финальной защитой повторить сценарий на актуальной сборке и используемом аккаунте API.

Локально пройдены 16 тестов, проверка типов, форматирование и сборка. Доступны рабочие маршруты `/`, `/api/search` и `/api/agent`.

Этапы отмечаются завершёнными после появления реализации и подтверждающих проверок. Бронирование, заявки подрядчикам и их уведомление не входят в текущий объём MVP.
