# LPV Match — roadmap

Статус отражает содержимое репозитория, а не готовность запланированных функций. Основание этапов — [план реализации команды](docs/IMPLEMENTATION.md). Обзор проекта и подготовка окружения — в [README](README.md).

## 0. Подготовка — выполнена

- [x] Зафиксированы задача, архитектура MVP и критерии готовности.
- [x] Определены TypeScript-контракты анкеты, запроса, результатов, оснований подбора и статистики API.
- [x] Добавлен шаблон окружения; локальные файлы с ключами исключены из Git.

Это подготовительные материалы. Проверка типов в составе сборки приложения ещё предстоит.

## 1. Каталог и алгоритм подбора — запланировано

- [ ] Импортировать официальный CSV и проверить 66 анкет, обязательные поля и метки происхождения данных.
- [ ] Реализовать ограничения по городу, категории, занятости, бюджету, формату, языку и длительности.
- [ ] Добавить детерминированное ранжирование со стабильным порядком при одинаковых баллах.
- [ ] Возвращать не более трёх анкет и различать `matched`, `no_category` и `no_matches`.
- [ ] Проверить граничные случаи тестами: занятость, превышение бюджета, ограничения и повтор одного запроса.

Условие завершения: результаты воспроизводимы, заданные ограничения соблюдаются, а причины исключения кандидатов проверяемы.

## 2. Интерфейс — запланировано

- [ ] Создать каркас приложения Next.js, зависимости и команды запуска.
- [ ] Реализовать форму и карточки подрядчиков с начальной ценой.
- [ ] Показывать причины пустой выдачи и действительное количество результатов, если найдено меньше трёх.
- [ ] Обновлять подбор при изменении даты и других условий.
- [ ] Добавить демонстрационные запросы на основе фактических данных каталога.

Условие завершения: пользователь проходит путь от ввода параметров до результатов и понимает причины отсутствия подходящих анкет.

## 3. Модели и расход API — запланировано

- [ ] Добавить серверный разбор естественного языка и проверку распознанных полей пользователем.
- [ ] Сформировать индивидуальные объяснения только из фактов об анкетах и результатов расчётов.
- [ ] Подключить настраиваемые модели для разбора и объяснений; проверить их доступность.
- [ ] Ограничить контекст выбранными анкетами и длину ответов, кешировать одинаковые запросы.
- [ ] Показывать модель, задачу, фактические токены, задержку и оценочную стоимость.
- [ ] Проверить локальный режим без ключа и при ошибке API с явным обозначением отсутствия LLM.

Условие завершения: модель не обходит фильтры, локальный поиск сохраняется при недоступности API, ключ не передаётся в браузер и диагностические ответы.

## 4. Проверка и демонстрация — запланировано

- [ ] Проверить сборку и независимый запуск из чистой копии репозитория.
- [ ] Подтвердить сценарии массовой категории, редкой категории и пустой выдачи.
- [ ] Сверить реализованные функции со всеми [критериями готовности](docs/IMPLEMENTATION.md#критерии-готовности).
- [ ] Дополнить README проверенными требованиями, командами установки, запуска и тестирования.
- [ ] Подготовить демонстрацию и описать оставшиеся ограничения.

Этапы отмечаются завершёнными после появления реализации и подтверждающих проверок. Бронирование, заявки подрядчикам и их уведомление не входят в текущий объём MVP.
