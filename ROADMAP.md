## 1. Каталог и алгоритм подбора — реализовано

- [x] Импортировать официальный CSV и проверить 66 анкет, обязательные поля и метки происхождения данных.
- [x] Реализовать ограничения по городу, категории, занятости, бюджету, формату, языку и длительности.
- [x] Добавить детерминированное ранжирование со стабильным порядком при одинаковых баллах.
- [x] Возвращать не более трёх анкет и различать `matched`, `no_category` и `no_matches`.
- [x] Проверить граничные случаи тестами: занятость, превышение бюджета, ограничения и повтор одного запроса.
- [x] Предлагать альтернативы даты и бюджета только после повторного поиска с соблюдением остальных условий.
- [x] Предлагать альтернативы и после успешного поиска, только если они расширяют выбор или снижают минимальную цену доступных анкет.

Реализация: [доменный модуль](src/domain/matching.ts), [схемы](src/domain/schema.ts), [импорт](scripts/import-catalog.ts) и [тесты](tests/matching.test.ts). Проверки охватывают 6600 запросов по официальному календарю. Локальные объяснения и проверяемые основания доступны в карточках.

## 3. Модели и расход API — реализовано

- [x] Добавить серверный разбор естественного языка, уточнения и отображение распознанных полей в редактируемой форме.
- [x] Сформировать индивидуальные объяснения только из фактов об анкетах и проверенных цитат.
- [x] Подключить настраиваемые модели для разбора и объяснений; проверить их доступность на аккаунте команды.
- [x] Ограничить контекст выбранными анкетами и длину ответов, кешировать одинаковые запросы.
- [x] Показывать модель, задачу, фактические токены, задержку и оценочную стоимость.
- [x] Проверить локальный режим без ключа и при ошибке API с явным обозначением отсутствия LLM.

Реализация: [агент](src/server/agent.ts), [сервис поиска](src/server/search-service.ts), [адаптер OpenAI](src/server/openai.ts). AI-тесты используют имитацию ответов провайдера; ручная проверка реального API описана командой в [RUNBOOK](docs/RUNBOOK.md). Модель не определяет состав и порядок выдачи, ключ используется на сервере. Доступность выбранных моделей на другом аккаунте нужно проверить отдельно.

## 5. Черновик, календарь, голос и избранное — подключены к интерфейсу

- [x] Добавить `/api/brief`: частичная заявка, недостающие поля и следующий вопрос, без автоматического поиска и выдуманных даты или бюджета.
- [x] Добавить `/api/calendar`: доступность, количество анкет в бюджете и минимальная начальная цена по всем 100 дням учебного календаря.
- [x] Добавить `/api/transcribe` и `OPENAI_MODEL_TRANSCRIBE`: проверка формата и размера, расшифровка без сохранения и кеша аудио.
- [x] Проверить новые модули тестами; ответы провайдера в тестах имитируются.
- [x] Подключить разговорный интерфейс к черновику и обновлять результаты только после подтверждения пользователем.
- [x] Подключить запись с микрофона: первое нажатие начинает запись, второе завершает и отправляет её; есть отмена, лимит 60 секунд и освобождение микрофона.
- [x] Подключить защиту ручных правок от устаревшего ответа помощника и отключить автоматическую прокрутку при голосовой обработке.
- [x] Добавить адаптивную панель результатов, мобильные вкладки и уведомления с явным переходом к обновлённым данным.
- [x] Добавить избранное с валидацией сохранённых данных и сохранением после перезагрузки браузера.
- [x] Обозначить изображения как демонстрационные AI-иллюстрации, не влияющие на ранжирование.
- [x] Проверить реальную транскрипцию синтетической записи и мобильный экран 390×844 — результаты команды в [VOICE-AND-BRIEF.md](docs/VOICE-AND-BRIEF.md).
- [ ] Перед демонстрацией проверить разрешения и запись с физического микрофона на используемом устройстве.

Локально в браузере без ключа проверены подтверждение перед подбором, смена даты через календарь и избранное после перезагрузки. Физический микрофон пользователя при проверках команды не записывался. Стоимость аудио пока возвращается как неизвестная.

## 6. Следующий приоритет — оценка качества по ТЗ

Команда приостановила расширение интерфейса в пользу проверки Definition of Done. Следующий шаг — оценить, насколько объяснения индивидуальны для выбранного подрядчика, опираются на источник и не могут без потери смысла быть переставлены между карточками. Это проверка качества, а не утверждение, что текущие объяснения уже прошли такую оценку.

Этапы отмечаются завершёнными после появления реализации и подтверждающих проверок. Бронирование, заявки подрядчикам и их уведомление не входят в текущий объём MVP.
