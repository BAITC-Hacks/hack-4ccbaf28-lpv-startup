# LPV Match

Проект команды **LPV StartUp** для задачи Firebird, трек «Креативные индустрии». Цель — помочь организатору мероприятия выбрать до трёх подрядчиков из каталога организаторов с объяснением, почему каждый подходит.

## Текущее состояние

Реализован локальный алгоритм подбора. В репозитории уже есть:

- план архитектуры, этапы реализации и критерии готовности;
- официальный CSV, проверенный каталог из 66 анкет и воспроизводимый импорт в JSON;
- TypeScript-контракты и валидация анкет и поисковых запросов;
- строгие фильтры, стабильное ранжирование, выдача до трёх анкет и причины исключения кандидатов;
- проверяемые предложения изменить дату или бюджет и локальные объяснения по фактам из анкет;
- тесты подбора, команды проверки типов и импорта;
- пример переменных окружения и исключение локальных ключей из Git.

**Веб-интерфейс и серверные API пока не добавлены.** Алгоритм можно проверять локально через тесты; интеграция моделей и учёт API ещё предстоят. Дальнейшие этапы и их статус — в [ROADMAP.md](ROADMAP.md).

## Планируемый сценарий

1. Пользователь указывает город, дату, категорию подрядчика, формат мероприятия и бюджет в тенге. Дополнительно — язык, длительность и пожелания к стилю.
2. Для запроса обычным текстом модель выделяет поля, которые пользователь проверяет перед поиском.
3. Приложение проверяет ограничения, исключает занятых подрядчиков и показывает до трёх подходящих анкет с индивидуальными объяснениями.
4. При изменении даты или других условий подбор выполняется заново.

Алгоритм уже различает три результата: `matched` — найдены подходящие анкеты; `no_category` — в городе нет нужной категории; `no_matches` — категория есть, но никто не проходит ограничения. Отображение этих состояний в интерфейсе ещё предстоит.

## Архитектура MVP

Планируется одно локально запускаемое приложение на **Next.js и TypeScript** с интерфейсом и серверными API. Отдельная база данных и GPU не предусмотрены.

| Компонент | Ответственность | Статус |
| --- | --- | --- |
| Локальный каталог | Импорт и проверка официального CSV с анкетами | Реализовано |
| Алгоритм подбора | Проверка города, категории, даты, бюджета, формата, языка и длительности; стабильное ранжирование | Реализовано |
| Локальные объяснения и альтернативы | Факты и выдержки из анкет; повторный поиск при предложенном изменении даты или бюджета | Реализовано в доменном модуле |
| LLM на сервере | Разбор свободного запроса и объяснения, основанные на фактах о выбранных кандидатах | Запланировано |
| Интерфейс | Форма, проверка распознанных полей, карточки и понятные причины отсутствия результатов | Запланировано |
| Учёт API | Модель, назначение запроса, токены, задержка, кеш и оценочная стоимость | Определён контракт; интеграции нет |

Модель не должна отменять ограничения, проверенные кодом. Для одинаковых входных полей алгоритм сохраняет порядок результатов; при равных баллах сортирует по идентификатору анкеты. Ранжирование учитывает запас бюджета и совпадения пожеланий с описанием, не ослабляя строгие фильтры. Каждая предложенная альтернатива меняет только дату или только бюджет и проходит полный повторный поиск.

Доменный модуль не обращается к LLM и не требует API-ключа. Явное обозначение локального режима в интерфейсе и обработка ошибок будущей интеграции провайдера ещё предстоят.

Подробности и критерии проверки: [план реализации](docs/IMPLEMENTATION.md).

## Данные и ограничения

В репозиторий добавлен каталог организаторов: **66 анкет с уникальными идентификаторами, из них 13 отмечены как синтетические**. Исходный [CSV](data/contractors.csv) преобразуется в [JSON](data/contractors.json) с валидацией полей и проверкой числа и уникальности идентификаторов. Повторный импорт воспроизводит сохранённый JSON без изменений. Происхождение данных описано в [data/SOURCE.md](data/SOURCE.md).

Контракт [Contractor](src/domain/types.ts) предусматривает начальную цену `price_from_kzt`, даты занятости `busy_dates`, допустимые форматы, языки и максимальную длительность. Метки `synthetic`, `city_imputed` и `price_imputed` сохраняют сведения о происхождении данных.

- Бюджет задаётся в KZT, дата — в формате `YYYY-MM-DD`.
- Цена в анкете — начальная, а не окончательное коммерческое предложение.
- Поиск принимает даты только с **23 сентября по 31 декабря 2026 года**. Отсутствие даты в `busy_dates` означает доступность в рамках учебного календаря; интеграции с живым календарём нет.
- `max_hours: null` означает отсутствие ограничения времени физического присутствия, согласно описанию источника.
- Бронирование, отправка заявок и уведомления подрядчикам не входят в MVP.
- Дообучение модели не планируется.

## Подготовка и запуск

Требования: **Node.js 22 или новее**, npm, Git и доступ к этому репозиторию. Проверено на Node.js 22.22.3 и npm 10.9.8.

```sh
git clone https://github.com/BAITC-Hacks/hack-4ccbaf28-lpv-startup.git
cd hack-4ccbaf28-lpv-startup
npm ci
cp .env.example .env.local
```

Для проверки каталога и алгоритма ключ не нужен:

```sh
npm run data:import
npm test
npm run typecheck
```

`data:import` перезаписывает `data/contractors.json` из исходного CSV. Команды выполняются из корня репозитория.

Переменные из [.env.example](.env.example):

| Переменная | Назначение | Значение в примере |
| --- | --- | --- |
| `OPENAI_API_KEY` | Ключ для будущих серверных обращений к OpenAI | Пустое |
| `OPENAI_MODEL_FAST` | Модель для разбора запроса | `gpt-5.4-nano` |
| `OPENAI_MODEL_REASONING` | Модель для объяснений | `gpt-5.4-mini` |

Имена моделей отражают начальную конфигурацию команды. Их доступность и вызовы API ещё не проверены; значения можно будет изменить под используемый аккаунт. Настоящий ключ хранится только в `.env.local`, который исключён из Git. В текущем коде переменные пока не используются.

В `package.json` уже определены `npm run dev`, `npm run build` и `npm start`, но страниц Next.js (`app` или `pages`) пока нет. **Запуск веб-приложения и production-сборка на этом этапе не подтверждены.** Полная инструкция запуска будет дополнена после появления интерфейса; `npm start` предполагает готовую сборку.

## Проверки

Проверено локально: `npm ci` завершён, `npm run data:import` воспроизвёл JSON без изменений, `npm test` — **8 из 8 тестов прошли**, `npm run typecheck` — без ошибок.

Набор из восьми тестов проверяет каталог, три состояния поиска, строгие ограничения и граничные значения, нормализацию ввода, стабильное ранжирование, лимит выдачи, допустимый календарь и альтернативы. Один тест выполняет **6600 запросов**: по 66 анкетам на каждый из 100 дней календаря, проверяя ограничения для всех возвращённых результатов.

Проверка веб-интерфейса, сборки и вызовов API ещё предстоит. Для демонстрации запланированы массовая категория, редкая категория и пустая выдача; условия перечислены в [roadmap](ROADMAP.md).
