# LPV Match

Проект команды **LPV StartUp** для задачи Firebird, трек «Креативные индустрии». Цель — помочь организатору мероприятия выбрать до трёх подрядчиков из каталога организаторов с объяснением, почему каждый подходит.

## Текущее состояние

Проект находится на этапе подготовки MVP. В репозитории уже есть:

- план архитектуры, этапы реализации и критерии готовности;
- TypeScript-контракты анкеты подрядчика, поискового запроса, результатов подбора и статистики обращений к модели;
- пример переменных окружения и исключение локальных ключей из Git.

**Работающего приложения пока нет.** Каталог анкет, алгоритм подбора, интерфейс, серверные API, интеграция моделей и тесты ещё не добавлены. Дальнейшие этапы и их статус — в [ROADMAP.md](ROADMAP.md).

## Планируемый сценарий

1. Пользователь указывает город, дату, категорию подрядчика, формат мероприятия и бюджет в тенге. Дополнительно — язык, длительность и пожелания к стилю.
2. Для запроса обычным текстом модель выделяет поля, которые пользователь проверяет перед поиском.
3. Приложение проверяет ограничения, исключает занятых подрядчиков и показывает до трёх подходящих анкет с индивидуальными объяснениями.
4. При изменении даты или других условий подбор выполняется заново.

Контракты различают три результата: `matched` — найдены подходящие анкеты; `no_category` — в городе нет нужной категории; `no_matches` — категория есть, но никто не проходит ограничения. Это определённые типы данных; обработка этих состояний ещё предстоит.

## Архитектура MVP

Планируется одно локально запускаемое приложение на **Next.js и TypeScript** с интерфейсом и серверными API. Отдельная база данных и GPU не предусмотрены.

| Компонент | Запланированная ответственность |
| --- | --- |
| Локальный каталог | Импорт и проверка официального CSV с анкетами |
| Алгоритм подбора | Проверка города, категории, даты, бюджета, формата, языка и длительности; стабильное ранжирование |
| LLM на сервере | Разбор свободного запроса и объяснения, основанные на фактах о выбранных кандидатах |
| Интерфейс | Форма, проверка распознанных полей, карточки и понятные причины отсутствия результатов |
| Учёт API | Модель, назначение запроса, токены, задержка, кеш и оценочная стоимость |

Модель не должна отменять ограничения, проверенные кодом. Для одинаковых входных полей планируется одинаковый порядок результатов; при равных баллах — сортировка по идентификатору анкеты. Без API-ключа или при ошибке провайдера должен сохраняться явно обозначенный локальный подбор. Эти механизмы пока не реализованы.

Подробности и критерии проверки: [план реализации](docs/IMPLEMENTATION.md).

## Данные и ограничения

По материалам команды, источник данных — каталог организаторов из **66 анонимизированных анкет**, включая синтетические и дополненные поля. Сам CSV в репозиторий ещё не добавлен, его импорт и количество записей не проверены.

Контракт [Contractor](src/domain/types.ts) предусматривает начальную цену `price_from_kzt`, даты занятости `busy_dates`, допустимые форматы, языки и максимальную длительность. Метки `synthetic`, `city_imputed` и `price_imputed` сохраняют сведения о происхождении данных.

- Бюджет задаётся в KZT, дата — в формате `YYYY-MM-DD`.
- Цена в анкете — начальная, а не окончательное коммерческое предложение.
- Проверка занятости будет опираться на даты из каталога; интеграция с живым календарём не заявлена.
- Бронирование, отправка заявок и уведомления подрядчикам не входят в MVP.
- Дообучение модели не планируется.

## Подготовка и запуск

Для получения проекта нужен Git и доступ к этому репозиторию:

```sh
git clone https://github.com/BAITC-Hacks/hack-4ccbaf28-lpv-startup.git
cd hack-4ccbaf28-lpv-startup
cp .env.example .env.local
```

Переменные из [.env.example](.env.example):

| Переменная | Назначение | Значение в примере |
| --- | --- | --- |
| `OPENAI_API_KEY` | Ключ для будущих серверных обращений к OpenAI | Пустое |
| `OPENAI_MODEL_FAST` | Модель для разбора запроса | `gpt-5.4-nano` |
| `OPENAI_MODEL_REASONING` | Модель для объяснений | `gpt-5.4-mini` |

Имена моделей отражают начальную конфигурацию команды. Их доступность и вызовы API ещё не проверены; значения можно будет изменить под используемый аккаунт. Настоящий ключ хранится только в `.env.local`, который исключён из Git. В текущем коде переменные пока не используются.

В репозитории ещё нет `package.json`, зависимостей и команд приложения. **Команды установки, запуска, сборки и тестирования будут добавлены после появления и проверки реализации.** Копирование файла окружения само по себе приложение не запускает.

## Проверки

Сборка приложения, тесты подбора и вызовы API ещё не выполнялись: соответствующая реализация отсутствует. Для готового MVP запланированы проверки строгих ограничений, стабильного порядка выдачи, индивидуальных объяснений и работы без LLM, а также три демонстрационных сценария: массовая категория, редкая категория и пустая выдача. Проверяемые условия перечислены в [roadmap](ROADMAP.md).
