# LPV Match

Проект команды **LPV StartUp** для задачи Firebird, трек «Креативные индустрии». Цель — помочь организатору мероприятия выбрать до трёх подрядчиков из каталога организаторов с объяснением, почему каждый подходит.

## Текущее состояние

Работает локальное веб-приложение на Next.js. Реализованы:

- форма поиска, карточки с объяснениями, демонстрационные запросы и состояния пустой выдачи;
- официальный CSV, проверенный каталог из 66 анкет и воспроизводимый импорт в JSON;
- TypeScript-контракты и валидация анкет и поисковых запросов;
- строгие фильтры, стабильное ранжирование, выдача до трёх анкет и причины исключения кандидатов;
- проверяемые предложения изменить дату или бюджет и локальные объяснения по фактам из анкет;
- AI-разбор свободного текста, уточняющие вопросы и объяснения с проверкой цитат;
- панель выполнения с использованными моделями, токенами, временем и оценкой стоимости;
- кеш ответов, локальный режим без ключа и сохранение результатов при отказе AI;
- тесты подбора и AI-интеграции, команды проверки типов, форматирования и сборки;
- пример переменных окружения и исключение локальных ключей из Git.

**Для поиска через форму API-ключ не нужен.** Собственный ключ OpenAI требуется для помощника, разбирающего свободный текст, и AI-объяснений. Статус этапов — в [ROADMAP.md](ROADMAP.md), подробный сценарий демонстрации — в [RUNBOOK](docs/RUNBOOK.md).

## Как пользоваться

1. Пользователь указывает город, дату, категорию подрядчика, формат мероприятия и бюджет в тенге. Дополнительно — язык, длительность и пожелания к стилю.
2. Нажимает «Найти своих людей»: приложение исключает неподходящих и занятых подрядчиков и показывает до трёх анкет с индивидуальными объяснениями.
3. С подключённым API может описать задачу в поле «Запрос помощнику». Агент задаёт уточнение либо выполняет поиск и обновляет поля формы по распознанным параметрам. Результат можно проверить и скорректировать через форму.
4. Меняет дату или другие условия и снова запускает подбор. Предложенную альтернативу бюджета или даты применяет отдельным нажатием.

Алгоритм и интерфейс различают три результата: `matched` — найдены подходящие анкеты; `no_category` — в городе нет нужной категории; `no_matches` — категория есть, но никто не проходит ограничения. Если кандидатов меньше трёх, показаны фактическое количество и причины ограничения выборки.

## Архитектура MVP

Одно локально запускаемое приложение на **Next.js, React и TypeScript** содержит интерфейс и серверные API. Отдельная база данных и GPU не нужны.

| Компонент | Ответственность | Статус |
| --- | --- | --- |
| Локальный каталог | Импорт и проверка официального CSV с анкетами | Реализовано |
| Алгоритм подбора | Проверка города, категории, даты, бюджета, формата, языка и длительности; стабильное ранжирование | Реализовано |
| Локальные объяснения и альтернативы | Факты и выдержки из анкет; повторный поиск при предложенном изменении даты или бюджета | Реализовано |
| LLM на сервере | Разбор свободного запроса, уточнения и выбор подтверждающих цитат | Реализовано; нужен свой ключ |
| Интерфейс | Форма, карточки, раскрываемые основания и причины отсутствия результатов | Реализовано |
| Учёт API | Модель, назначение запроса, токены, задержка, кеш и оценочная стоимость | Реализовано в панели выполнения |

Модель не должна отменять ограничения, проверенные кодом. Для одинаковых входных полей алгоритм сохраняет порядок результатов; при равных баллах сортирует по идентификатору анкеты. Ранжирование учитывает запас бюджета и совпадения пожеланий с описанием, не ослабляя строгие фильтры. Каждая предложенная альтернатива меняет только дату или только бюджет и проходит полный повторный поиск.

Доменный модуль не обращается к LLM. При отсутствии ключа, отключении AI-объяснений или ошибке объясняющей модели сохраняется локальный подбор с цитатами из каталога. Ошибка разбора свободного текста сообщается явно: помощник не заменяет запрос произвольными параметрами.

### Как используется AI

- `/api/agent` получает текст, текущие поля формы и до четырёх сообщений истории. Быстрая модель выбирает `search_contractors` или `ask_clarification`; аргументы проверяются схемой Zod.
- `/api/search` выполняет поиск по структурированным полям. Модель не изменяет состав кандидатов и порядок ранжирования.
- Для объяснений сервер передаёт модели только основания и фрагменты описаний выбранных кандидатов — максимум трёх. Полученная цитата должна точно совпасть с допустимым фрагментом анкеты; иначе остаётся локальное объяснение.
- Для сложных объяснений используется `OPENAI_MODEL_REASONING`, для коротких — `OPENAI_MODEL_FAST`. Сложность определяется пожеланиями длиннее 15 символов либо одновременно заданными языком и длительностью.
- Ответы кешируются на 30 минут в памяти процесса, максимум 150 записей. Кеш исчезает после перезапуска; повторное использование ответа не создаёт нового вызова модели.
- Панель «Как это работает» показывает этапы, модели, фактическое `usage`, время и расчётную стоимость. Статистика относится к текущей вкладке, а не всему аккаунту; для неизвестного тарифа стоимость не вычисляется.

Подробности и критерии проверки: [план реализации](docs/IMPLEMENTATION.md).

## Данные и ограничения

В репозиторий добавлен каталог организаторов: **66 анкет с уникальными идентификаторами, из них 13 отмечены как синтетические**. Исходный [CSV](data/contractors.csv) преобразуется в [JSON](data/contractors.json) с валидацией полей и проверкой числа и уникальности идентификаторов. Повторный импорт воспроизводит сохранённый JSON без изменений. Происхождение данных описано в [data/SOURCE.md](data/SOURCE.md).

Контракт [Contractor](src/domain/types.ts) предусматривает начальную цену `price_from_kzt`, даты занятости `busy_dates`, допустимые форматы, языки и максимальную длительность. Метки `synthetic`, `city_imputed` и `price_imputed` сохраняют сведения о происхождении данных.

- Бюджет задаётся в KZT, дата — в формате `YYYY-MM-DD`.
- Цена в анкете — начальная, а не окончательное коммерческое предложение.
- Поиск принимает даты только с **23 сентября по 31 декабря 2026 года**. Отсутствие даты в `busy_dates` означает доступность в рамках учебного календаря; интеграции с живым календарём нет.
- `max_hours: null` означает отсутствие ограничения времени физического присутствия, согласно описанию источника.
- Бронирование, отправка заявок и уведомления подрядчикам не входят в MVP.
- Дообучение модели не планируется.

## Подготовка и запуск

Требования: **Node.js 22 или новее**, npm, Git и доступ к этому репозиторию. Проверено на Node.js 22.22.3 и npm 10.9.8.

```sh
git clone https://github.com/BAITC-Hacks/hack-4ccbaf28-lpv-startup.git
cd hack-4ccbaf28-lpv-startup
npm ci
cp .env.example .env.local
npm run dev
```

Откройте **http://127.0.0.1:3000**. Без ключа доступны форма, каталог, строгий поиск, альтернативы и локальные объяснения. JSON уже включён в репозиторий: повторный импорт для запуска не требуется.

Для запуска production-сборки остановите dev-сервер, затем выполните:

```sh
npm run build
npm start
```

Команды выполняются из корня репозитория. Сервер слушает только `127.0.0.1`. Другой порт: `npm run dev -- --port 3001` или `npm start -- --port 3001`.

### Настройка OpenAI

Добавьте свой ключ в `.env.local` и перезапустите сервер. Ключ используется только на сервере; файл исключён из Git.

Переменные из [.env.example](.env.example):

| Переменная | Назначение | Значение в примере |
| --- | --- | --- |
| `OPENAI_API_KEY` | Ключ для серверных обращений к OpenAI | Пустое |
| `OPENAI_MODEL_FAST` | Разбор запроса и короткие объяснения | `gpt-5.4-nano` |
| `OPENAI_MODEL_REASONING` | Объяснения для сложных запросов | `gpt-5.4-mini` |

Команда описала проверку реальных вызовов этих моделей в [RUNBOOK](docs/RUNBOOK.md); доступность на вашем аккаунте может отличаться. При замене модели требуется совместимость с используемыми Responses API, function calling, Structured Outputs и `reasoning.effort: none`. Текущая реализация ограничивает вызов таймаутом 6,5 секунды и длину ответа — максимум 1100 выходных токенов; для объяснений лимит 1000.

API ограничен 30 запросами в минуту на локальный процесс. В MVP нет регистрации, бронирования и интеграции NVIDIA.

## Демонстрация

| Сценарий | Действие | Ожидаемый результат |
| --- | --- | --- |
| Массовая категория | «Ведущий на корпоратив» | Мицури Канроджи, Буллма, Хаул — в этом порядке |
| Занятость | В том же запросе изменить дату на 17.10.2026 и выполнить поиск | Мицури исключён; Буллма, Хаул, Кики |
| Редкая категория | «Камерная флористика» | Одна анкета — Тони Тони Чоппер; объяснение сокращённой выдачи |
| Пустая выдача | «Проверить ограничения» | Нет совпадений; предложен бюджет 650 000 ₸ с одним подходящим кандидатом |
| Нет категории | Для флористики выбрать «Зарубежье» и выполнить поиск | Отдельное сообщение об отсутствии категории |

Для AI-сценария и показа расхода API следуйте [плану демонстрации](docs/RUNBOOK.md#сценарий-демонстрации-34-минуты). Результаты выше относятся к текущему учебному каталогу.

## Проверки

```sh
npm test
npm run typecheck
npm run format:check
npm run build
```

Проверено локально: установка из lock-файла, **16 из 16 тестов**, типы, форматирование и production-сборка проходят. Собранный сервер запущен без API-ключа; через HTTP подтверждены основные сценарии, смена даты, альтернативный бюджет и понятный ответ помощника без ключа. В браузере проверены карточки, редкая категория и пустая выдача.

Тесты охватывают каталог, состояния поиска, строгие ограничения, стабильный порядок, календарь и альтернативы. Один тест выполняет **6600 запросов** по официальному календарю. AI-тесты проверяют недопустимые цитаты, сохранение состава кандидатов, кеш, отказ провайдера, уточнения, валидацию аргументов, проверку источника HTTP-запроса и расчёт стоимости.

Автоматические тесты не требуют ключа и используют имитацию ответов провайдера. Реальные API-вызовы отдельно проверены командой; наблюдения зафиксированы в [RUNBOOK](docs/RUNBOOK.md). Измеренная скорость и стоимость одного запроса не являются гарантией для других запросов.

Для повторного импорта: `npm run data:import`. Команда валидирует CSV и перезаписывает `data/contractors.json`.
